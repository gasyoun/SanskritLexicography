## Two documentation defects found while following the skill

Both cost a failed invocation each; neither spent a paid call (both aborted as
`configuration` / file-not-found *before* any call was issued), but both would cost a
human the same two attempts.

1. **`/pwg-live-gate` Step 2b omits `CLAUDE_CONFIG_DIR`.** The documented paste fails with
   `{"classification": "configuration", "error": "CLAUDE_CONFIG_DIR is required for manifest v2"}`.
   [`headless_worker.py:1630`](https://github.com/gasyoun/SanskritLexicography/blob/master/RussianTranslation/src/pilot/headless_worker.py)
   reads the config dir from the environment only — `--only-profile` does not supply it, and
   the manifest's own `config_dir_fingerprint` is a *check*, not a source. The command needs
   `CLAUDE_CONFIG_DIR=<that profile's dir>` prefixed.
2. **The skill's `--timeout` prose is stale.** It states, in bold, that "300 000 ms is an
   absolute maximum, and above it is now REFUSED" (H2254, 07-08-2026), and instructs
   `--timeout 300, not 180`. The live constant is
   `execution_contract.PRODUCTION_HARD_TIMEOUT_MS = 600000`, and `canary_manifest_build.py`
   itself now prints `--timeout 600` in its paste-ready next command. The skill's numeral has
   now gone stale for the third time (180 → 300 → 600) in the same way its ceiling numerals
   did (30 000 → 65 000 → 80 000), and for the same reason: a literal restated in prose beside
   a constant that is the real contract. The fix is the one the ceiling line already adopted —
   derive and point at the constant, never restate the number.

**Does not settle: the H858 window's stop condition may not be satisfiable by any single
window as currently written.** H3144 asks for a bounded no_pwg window showing the
`{#…#}`-drop null class eliminated **and** `summary.german_anchor_repairs > 0`. Those two
clauses pull against each other: `german_anchor` only fires on a card that ALREADY failed the
`<ls>`/`{#` count, so a window in which no card drops a span reports `german_anchor_repairs:
0` — which is the repair having nothing to do, not the repair failing. Today's canary is
exactly that case (`german_anchor_repairs: 0`, `german_anchor_detail: []`, one clean card).
Note also that the three H858 null-class keys still in
[`no_pwg_residuals.jsonl`](https://github.com/gasyoun/SanskritLexicography/blob/master/RussianTranslation/src/pilot/no_pwg_residuals.jsonl)
(`asa_mskfta`, `avy_ahata`, `avyagra`) are ledgered as
`second consecutive selfheal-nothing-resolved on presplit card` — a **different** class from
the `{#` count drop — so re-running just those keys need not exercise `german_anchor` either.
A human should decide whether the measurement is "repairs > 0 on a window sized to contain
drops", "the null class is absent from a fresh window", or a targeted replay of cards known to
drop spans. Running a paid window against an unsatisfiable predicate is how a NO-GO gets
recorded for a working fix.
