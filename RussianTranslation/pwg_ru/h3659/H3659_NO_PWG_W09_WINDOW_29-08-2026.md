## The blocker is mechanical, and human spend authorization cannot clear it

This is the finding of the session, and it **supersedes H3659's own premise**. The handoff was
written as though the last remaining gate were a human ruling on billing. It is not. There are
two gates, and the second is code:

1. **Human authorization** — obtained 29-08-2026 ("spend one bounded c1 window under unknown
   billing"). Cleared.
2. **`bounded_supervisor`'s fail-closed cost guard** — *not* cleared, and authorization is the
   wrong kind of key for it.

[`bounded_supervisor.py`](https://github.com/gasyoun/SanskritLexicography/blob/master/RussianTranslation/src/pilot/bounded_supervisor.py)
checks, at the **top of the drain loop, before pulling any work**:

```python
if self.budget_cap is not None and not self._durable_cost_evaluable:
    self._finish(STOP_COST_UNEVALUABLE)
    break
```

`--cost-ceiling` sets `budget_cap`. Max-route calls return **no usage telemetry**, so the two
probe calls landed in the reservation ledger unpriced, `_durable_cost_evaluable` went false, and
the first loop iteration stopped. The guard tests **telemetry, not permission** — a human saying
"spend it" changes nothing, because the runner is not asking whether it *may* spend, it is
refusing to continue on a window it cannot **price**.

That is the same dormant Max-route credit accounting that closed
[H2591](https://github.com/gasyoun/Uprava/blob/main/handoffs/archive/H2591-Opus_SanskritLexicography_pwg-flash-prep-claude-bounded-context-compare_12.08.26.md)
❌ INCONCLUSIVE — expressed this time not as an unreadable receipt after the fact, but as a hard
refusal before the fact. **While billing telemetry is dormant, a cost-bounded window on this lane
is not merely unpriced; it is unrunnable.**

### The disclosed escape, named and NOT taken

`--allow-unbounded` (H2157) drops the `--cost-ceiling` requirement, leaving `budget_cap = None`,
which skips the guard. `--max-calls` and `--max-windows` bind independently of `budget_cap`, so
`--allow-unbounded --max-calls 8 --max-windows 1` would still be bounded in calls and windows —
unbounded only in dollars, which are unmeasurable in this lane either way.

It was **not used**. The flag exists to be "visible-in-command-review" for a *deliberate*
unbounded window; the authorization on record was for a **bounded** one. Substituting one for
the other on an agent's own judgment is exactly the guard-tunnelling defect recorded at H2851.
The choice belongs to a human, stated in these terms.

a linked worktree starts with that state empty. Two of the three would have caused real damage
silently:

| # | Tool | What it read | Failure in a worktree |

| 1 | `h963_c4_gate0_probe.py` | evidence root, checkout-relative | **Refused, correctly** — the append-only probe series would die with the worktree (#1034). Set `PWG_EVIDENCE_DIR` outside every checkout. |

| 3 | `bounded_staged_run.py` | validated-account roster, `max_orchestrator.sqlite` | **`--only-profile is not a validated roster slot`**, and it silently *created an empty DB at the worktree root*. Real roster is `src/pilot/max_orchestrator.sqlite` in the main tree (one row: `c1`, `validated=1`). Pass `--db` explicitly. |

The codebase already contains the correct pattern —
[`store_path.canonical_store`](https://github.com/gasyoun/SanskritLexicography/blob/master/RussianTranslation/src/store_path.py)

applied to the store and to nothing else.

in the main tree destroys it, and no paid window can start until it is rebuilt by hand.
