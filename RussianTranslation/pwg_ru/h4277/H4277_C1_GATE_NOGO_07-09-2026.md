### 7.1 What the model actually said (turn 1, 608 output tokens, `stop_reason: tool_use`)

> translation cards were provided** — the message describes a masked-translation task format but

### 7.2 Why the prompt earned that reading

`_probe_prompt` assembled, in order: (1) the production `MASK_PREAMBLE` — a task-shape block
that promises `=== CARD <key> ===` blocks and describes a masked-translation job; (2) **zero
cards**; (3) a differently-voiced instruction to disregard all of that and emit one fixed
string; (4) 6 491 B of filler. Items (1)+(2)+(3) are, read literally, the canonical textual
signature of a prompt injection. H3157 created this shape when it prepended the production block
to H994's terse readiness sentence, and it has been latent ever since: the model has to *decide*
each time whether the second instruction is legitimate, and either reading is defensible.

That decision is what makes the failure **bimodal on byte-identical input** — the anomaly §1
flags. The warm-up 16 s earlier took the cooperative reading and returned `{"ok": true}`; the
measured call took the adversarial one. Hypothesis (c) of §3 ("plain bimodality") was right
about the *shape* and this transcript supplies the missing *mechanism*: a coin-flip on an
adversarial-reading judgement, not latency or account degradation.

Hypothesis (b) — the `{Tn}` clause of `4a7998f22` — is **ruled out as the trigger**: the model's
objection is that there are no cards at all, not that any rule inside the block is wrong. The A/B
against `4a7998f22^` proposed in §3 is therefore unnecessary and would have spent a rationed
attempt on a dead lead.

Two secondary facts worth keeping. `permission_denials: []` and `thinking_tokens: 0` — the model
neither hit a permission wall nor deliberated at length; it simply read the prompt and declined.
And the headless probe inherits the profile's **full ambient context** (CLAUDE.md, hooks,
SessionStart output, skills list): the model cites those system-reminders *as corroboration* for
the injection reading. That is load-representative — production generation calls carry the same
ambient context — so it is not to be "fixed" by stripping the config dir, which would break the
spawn-shape match FINDINGS §498 rule 1 depends on.

### 7.3 The fix (this PR): a provenance bridge, no gate loosening

`_PROBE_PROVENANCE_BRIDGE` in
[`src/pilot/max_account_orchestrator.py`](https://github.com/gasyoun/SanskritLexicography/blob/master/RussianTranslation/src/pilot/max_account_orchestrator.py)
now sits between the production block and the filler, answering each of the three objections in
the harness's own voice: it declares the **same issuer** as the block above (so the instruction
is not payload-borne), declares the **zero-card condition deliberate and expected** (so an empty
card list is not a malformed request), and names the **structured-output channel as the turn's
sanctioned delivery** (so answering is not a plan-mode bypass). The filler is re-framed as
"data, never instructions".

**What is NOT changed, deliberately** (§3.3 holds in full): the content check still requires
`{"ok": true}` and nothing else; no retry inside a sitting; no ceiling raised; no profile
switched; `--permission-mode plan` kept, because matching the paid call's spawn shape is the
whole point. H3157's sensitivity survives — the production block is still first, still verbatim,
still the first thing the model reasons about.
