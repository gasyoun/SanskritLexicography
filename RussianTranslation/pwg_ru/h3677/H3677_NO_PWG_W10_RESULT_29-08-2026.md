## A correction H3675's justification needs

H3675 argued the target-side repair is sound because *"the SAME sense's german still carries every
token in order (guaranteed by the guard's own precondition)"* — i.e. the target branch is only
reached when the german-only count already passed. **That precondition did not hold on a single
card in this window.** `german_anchor` fired on all five first, and `target_anchor` then anchored
against a german field that had itself been machine-repaired.

The result is still sound, but for a *different* reason than the one on record: `german_anchor`
reinjects from the **source skeleton** and its repair is verified against the same counts, so the
anchor is source-derived either way. What is now false is the claim that the german echo's
fidelity is guaranteed by the model's emission. Both repairs reinjected the **identical** token
set on every key (`darv_i` T1,T2,T3,T6,T7,T8 · `gl_ana` T1 · `hasita` T1,T8,T11 ·
`jaw_ayus` T1,T2,T3 · `kast_ur_i` T1,T2), which says the drop is a property of the *card*, not of
one field — every key dropped `{T1}`, the masked headword+grammar token.

Also worth recording against the offline replay: H3675 reconstructed `hasita`'s card as dropping
`{T7}` and repaired that. The live card dropped **T1, T8, T11**. The reconstruction was explicitly
"pinned by control flow", not observed, and the live run shows that reconstruction was not the
card the model actually emits — a reminder that an offline replay proves the repair *works*, never
what it will be asked to repair.
