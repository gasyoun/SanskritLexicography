## Known limitations

- DeepSeek V4 Pro cache behavior is not yet measured successfully; Flash telemetry cannot substitute for it.
- The ≥20% economic threshold is ruled, but sample power depends on the bounded cohort that clears the transport gate.
- The current plan does not authorize canonical promotion, default-model changes, or sibling-repository edits.
- Provider pricing and cache semantics are time-sensitive and must be sealed per run.

## Intended use / known misuse

Use this plan to implement and judge one bounded, promotion-dry PWG caching programme. Do not cite it as evidence that Pro is cheaper, that a route is production-ready, or that a cache hit equals an accepted translation. Do not use deadline pressure to bypass the experiment ladder.

## Maintenance and sunset plan

The SanskritLexicography `RussianTranslation` pipeline owns the subject. Update it when an implementation changes a named contract or when live evidence closes a backlog item. Supersede it with a shared-package plan only after the two-lane gate passes; retain this file as the PWG decision record.
